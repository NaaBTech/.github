NaaB Tech (ناب تک) is a technology company focused on building secure software and delivering practical cybersecurity, networking, and infrastructure engineering.

The work is guided by a simple position: security is not a final review step before release, it is a design constraint applied from the first line of code and the first network diagram.

## Engineering Principles

These principles describe how work is approached. They apply to code, to documentation, and to systems handed over to a client.

| Principle | Meaning |
| --- | --- |
| **Security by Design** | Security requirements are identified and addressed at design time, not retrofitted after an incident. |
| **Quality and Reliability** | Work is verified before it is delivered. Reliability is a property of the design, not a side effect of testing. |
| **Maintainable Software** | Code is written to be read, changed, and owned by someone who was not its original author. |
| **Open Documentation** | Decisions, assumptions, and limitations are written down where the next engineer can find them. |
| **Responsible Security Research** | Security testing is scoped, authorized, and proportionate to the system in question. |
| **Continuous Improvement** | Incidents, defects, and retrospectives produce changes to the process, not only to the code. |

## Open Source and Collaboration

Not every NaaB Tech project is open source. Some work is delivered as a client engagement, some is internal tooling, and some is published publicly. Public repositories are released with an explicit license so that others can use, inspect, and build on them.

Where a repository is public, contributions are welcome:

- Open an issue before starting significant work, so effort is not duplicated and the direction can be discussed.
- Follow the [contribution guidelines](../CONTRIBUTING.md) and the [Code of Conduct](../CODE_OF_CONDUCT.md).
- Keep pull requests focused, explain the reasoning behind a change, and include testing evidence where it applies.
- Individual repositories may define stricter or more specific requirements. Where they do, those requirements take precedence over the organization-level guidance.

Security issues are handled separately and in private. Follow the [security policy](../SECURITY.md) instead of opening a public issue. NaaB Tech follows a coordinated disclosure process and does not ask reporters to publish findings before a fix is available.
